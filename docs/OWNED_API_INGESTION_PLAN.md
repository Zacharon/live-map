# Owner-operated evidence API plan

Local design only. No account, database, queue, schedule, deployment or source activation is provisioned. Reuse `/api/events`, `/api/changes`, `/api/sources`, `/api/provider-health` and `/api/moving-objects`; preserve Netlify/Cloudflare compatibility. An owned API aggregates authorized observations; it cannot create unobserved ships, cargo manifests, flights outside receiver coverage or satellite imagery.

1. **Prove the existing USGS stored path on its intended runtime.** Extend the existing `db/migrations/001_usgs_evidence.sql`, `002_usgs_recovery.sql` and collector/read-model/outbox model after native/PostGIS concurrency and restore checks. Do not create a parallel database/dashboard. Existing collection and stored-read flags plus DB source policy remain off until separately approved.
2. **Register each source's policy before collecting.** Existing source/adapter registry records carry access, attribution, terms review, coverage, cadence, retention and limitations. Add explicit catalogued / connector implemented / locally tested / live activated evidence, spend class, account owner and redistribution status. Missing permission or quota is unknown. Store immutable source-namespaced observation IDs and revisions with source URLs; syndicated origins do not gain independent corroboration.
3. **Central collection and budgets.** One server queue/collector per source, fixed hosts, bounded viewport/AOI/station/district watchlists, conditional retrieval where documented, shared cache, coalescing, source-specific byte/record/time caps, daily request budget and circuit/backoff state. Use durable/distributed quota coordination before scaling beyond one warm instance. CelesTrak stops on non-200; it does not enter generic retries. Separate ODbL aircraft data from other licenses; never mirror full publisher documents by default.
4. **Read models and chronology.** Store actual observation/advisory/element epoch, publication/update, retrieval and processing times separately. Preserve units, coverage/exclusions, method, confidence, source health and revision vintage. Missing records in a bounded feed are not deletion and not zero flow. Only explicit withdrawal/expiry may retire a current item. Missing geometry stays non-geographic. No browser upstream credentials or fallback requests.
5. **Expose existing envelopes with compatible optional provenance.** Vessels retain AIS location-record clocks, sentinel normalization, coverage and cargoManifest=null unless a real reviewed manifest source is added. Aircraft retain seen_pos, source clock and ADS-B/MLAT origin. Orbits declare propagation method/time vs element epoch. Imagery declares acquisition/processing date and layer-specific rights. Public source health includes last successful fetch, age, unavailable/no-coverage/clock-skew and rate limits without raw secrets. Inspector/list selection uses the existing shared state and globe highlight.
6. **Maritime assessment stays four independent signals.** AIS observations, explicitly inferred dark traffic, declared cargo-confirmed/published cargo estimates, and security reports retain their own clocks/coverage/unknowns. Diplomacy remains an operating dimension separate from physical flow. Contradictory estimates remain separately inspectable; do not average them into a recovery score.
7. **Acceptance and activation decision.** Run adapter schemas with real bounded public responses, revision/withdrawal/failure/retention tests, deployed route parity, independent H3 and native concurrency/restore proof. Owner decides hosting/resources, source activation and publication separately. Free public APIs may still require paid hosting/egress at scale; choose resource caps before enabling. Hard zero-paid upstream budget remains this deployment's default; optional forks use their own server accounts/billing and a genuine hard spend limiter.

Delivery stages: current candidate has direct list/ledger inspection, three off-by-default public adapters and policy interface. Existing USGS durable collector is local proof. New multi-source durable scheduling, hosted storage, distributed budgets, production licensing/ODbL review and source activation remain planned.
